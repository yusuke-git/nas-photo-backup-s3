# 料金の見張りと設定変更

バックアップを動かし始めたあとに、料金の急増に気づいたとき・自動ストップが発動したとき・`infra/` の設定を変えるときの対応をまとめたページ。セキュリティ面の対策は [セキュリティ点検](security.md) を参照。

## 料金の暴走対策 {#cost-guard}

予算アラート・自動ストップ・異常検知が、それぞれどの事故に効くかの一覧。各リソースの中身は [Terraform の解説の budget.tf](infra.md#budget)。

| 起きること | 対策 | 止まるか |
|---|---|---|
| `nas-backup` のキーが漏れ、大量にアップロードされる | Budget Actions が書き込みを自動で拒否 | 止まる（Budgets の更新が数時間遅れるため、その日のうち） |
| 管理者の認証情報が漏れ、EC2 などを起動される | Cost Anomaly Detection が通知 | 止まらない。管理者は SSO＋MFA にしてアクセスキーを作らないことで防ぐ |
| 全件の復元や `DEST` の書き間違い | 予算アラートと異常検知が通知 | 気づける |

## 自動ストップが発動したら {#auto-stop}

1. 予算超過と異常検知のメールで、どのサービスの課金が増えたかを確認する
2. キー漏えいが疑われる場合は、`aws iam delete-access-key` で `nas-backup` のキーを無効にし、新しいキーを発行する
3. 原因を解消したら、コンソールの Budgets → 該当予算 → アクションで「元に戻す」を実行する（`nas-backup-deny-write` ポリシーが外れる）

正当な理由（大量の写真を追加した月など）で予算を超えた場合もバックアップが止まる。その場合は `monthly_budget_usd` を上げて `terraform apply` してから元に戻す。

## AWS の設定を変えるとき {#change}

- 設定を変えるときは `infra/*.tf` を編集し、PR を出してから `terraform plan` と `terraform apply`
- `terraform plan` で `destroy` や `replace` が出たら、apply する前に内容を確認する
- AWS への操作（apply、アクセスキーの発行・削除など）は、実行する前に本人が内容を確認する
- 変更したら [構築記録](records.md#aws) に日付と内容を書く
